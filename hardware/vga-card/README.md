# VGA video card from discrete logic

Generates **800×600 @ 60 Hz** VGA timing from a **10 MHz** oscillator using
74-series counters and gates, and shows a **100×75, 64-colour** picture stored in
an EEPROM through a resistor DAC. Inspired by Ben Eater's video card
([eater.net/vga](https://eater.net/vga)); the timing derivation, decoder design,
pixel-latch pipeline and all the tools here are worked out from the VESA spec in
this repo. The full explanation is in [`notes/11-vga-card.md`](../../notes/11-vga-card.md).

## Timing (VESA 800×600 @ 60 Hz, ÷4 horizontally)

|            | visible | front porch | sync | back porch | total | rate |
|---|---|---|---|---|---|---|
| horizontal (10 MHz clocks) | 200 | 10 | 32 | 22 | **264** | 37.879 kHz |
| vertical (lines)           | 600 | 1  | 4  | 23 | **628** | 60.32 Hz |

Both syncs are positive. Image pixel = 2 clocks × 8 lines → 100 × 75.

## Block diagram

```
 10 MHz ──┬─► H counter (3× 74LS163, 0..263) ──┬─ bits 7..1 = x ─┐
          │        │ hclear = "263" (sync clear)│                 ├─► 28C256 ─► 74HCT374 ─► R/G/B DAC ─► VGA
          │        └─ lineEnd ─► V counter enable                  │  (A6..A0=x,   pixel latch     620 Ω / 1.2 kΩ
          │                     (3× 74LS163, 0..627) ─ bits 9..3 = y┘   A13..A7=y)   /OE = blank
          │
          └─► 4 J-K flip-flops (2× 74LS109), J/K from AND-gate decoders:
                hsync, vsync  ─────────────────────────────► VGA pins 13, 14
                hdisplay AND vdisplay ─ NAND ─► latch /OE  (blanking)
```

## Design decisions

1. **Everything synchronous.** 74LS163 counters clear synchronously and every
   output comes from a clocked flip-flop, so decoder glitches never reach the
   monitor. To change at count N, a flip-flop decodes N−1.
2. **Decoders generated, then verified.** `vga_timing.py` finds the fewest AND-gate
   inputs per event and proves them with a simulated cycle. The obvious shortcut
   (decode only the 1-bits) breaks hsync; see `test_naive_decoding_breaks_hsync`.
3. **Pixel latch.** A 28C256 needs up to 150 ns to answer; one pixel lasts 200 ns.
   The 74HCT374 grabs the data at the end of each pixel and shows it during
   the next one, so the picture is clean but 2 clocks late. The display
   window is shifted by those 2 clocks to match. Its `/OE` doubles as blanking.
4. **HCT for the DAC driver.** It needs TTL-compatible inputs (fed by LS chips)
   and CMOS outputs that hold ~4.5 V at the DAC's ~6 mA, which LS outputs can't.

## Decoder wiring (generated by `python3 vga_timing.py`)

| Signal | Set (J) when | Reset (K) when |
|---|---|---|
| H counter clear | `Q8 Q2 Q1 Q0` (263) | |
| hdisplay | `Q0 /Q8 /Q7` (1) | `Q7 Q6 Q3 Q0` (201) |
| hsync | `Q7 Q6 Q4 Q0 /Q5` (209) | `Q5 Q4 Q0` (241) |
| V counter clear | `Q9 Q6 Q5 Q4 Q1 Q0` · lineEnd (627) | |
| vdisplay | `Q5 Q4 Q1 Q0` · lineEnd (627) | `Q9 Q6 Q4 Q2 Q1 Q0` · lineEnd (599) |
| vsync | `Q9 Q6 Q4 Q3 /Q2` · lineEnd (600) | `Q2` · lineEnd (604) |

## DAC (per colour, 2 bits)

```
latch Q(MSB) ──[ 620 Ω ]──┬──► VGA R, G or B   (monitor: 75 Ω to ground)
latch Q(LSB) ──[ 1.2 kΩ ]─┘
```
Levels: 0, 0.24, 0.46, 0.70 V. Byte layout: `00RRGGBB`.

## Parts

10 MHz crystal oscillator · 6× 74LS163 · 2× 74LS109 · 74LS21 / 74LS08 / 74LS04 /
74LS00 for decoding · 28C256 EEPROM · 74HCT374 · 3× 620 Ω, 3× 1.2 kΩ · DE-15 (VGA) connector

## Tools

```bash
python3 vga_timing.py                     # derivation, decoder table, DAC values
python3 image_to_rom.py --test-pattern    # or: image_to_rom.py picture.png [--dither]
python3 vga_sim.py                        # measure the signals, render build/frame.png
python3 tests/test_vga.py
```
`image_to_rom.py` also writes the header for the
[EEPROM programmer](../eeprom-programmer/) (set `IMAGE_CHOICE 3`).
